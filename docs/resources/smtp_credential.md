# ahasend_smtp_credential (Resource)

Manages an AhaSend SMTP credential. There is no API update endpoint; changing `name`, `scope`, `sandbox`, `domains`, or `account_id` forces a new resource. The one-time `password` is returned on create and preserved in state. For Platform Partner sub-account credentials in the same root module, set `account_id` to the child account and `api_key` to that child's API key (for example from `ahasend_sub_account_api_key`).

## Example Usage

```terraform
terraform {
  required_providers {
    ahasend = {
      source = "goalgorilla/ahasend"
    }
  }
}

provider "ahasend" {
  api_key    = var.ahasend_api_key
  account_id = var.ahasend_account_id
}

variable "ahasend_api_key" {
  type      = string
  sensitive = true
}

variable "ahasend_account_id" {
  type = string
}

resource "ahasend_smtp_credential" "example" {
  name    = "app-smtp"
  scope   = "global"
  sandbox = false
}
```

### Sub-account SMTP credential

```terraform
resource "ahasend_sub_account_api_key" "smtp" {
  sub_account_id = ahasend_sub_account.project.id
  label          = "terraform-smtp"
  scopes = [
    "smtp-credentials:read:all",
    "smtp-credentials:write:all",
    "smtp-credentials:delete:all",
  ]
}

resource "ahasend_smtp_credential" "child" {
  account_id = ahasend_sub_account.project.id
  api_key    = ahasend_sub_account_api_key.smtp.secret_key
  name       = "opensocial-smtp"
  scope      = "scoped"
  domains    = ["mail.customer.example.com"]
  sandbox    = false
}
```

## Schema

### Required

- `name` (String) Unique credential name within the account. Changing this forces a new resource.
- `scope` (String) Credential scope: `global` or `scoped` (requires `domains`). Changing this forces a new resource.

### Optional

- `account_id` (String) Account UUID that owns the SMTP credential. Defaults to the provider `account_id`. Set this to a sub-account UUID when managing a child credential (with a matching child `api_key`).
- `api_key` (String, Sensitive) Optional Bearer token for this resource's API calls. When set, overrides the provider `api_key` so a child sub-account key can manage that child's SMTP credential in the same apply as `ahasend_sub_account_api_key`. Stored sensitive in state (required for Read/Delete; write-only is not available on Read). Omit to use the provider credentials.
- `domains` (List of String) Domain names for a `scoped` credential. Required when `scope` is `scoped`; must be omitted or empty when `scope` is `global`. Changing this forces a new resource.
- `sandbox` (Boolean) When true, the credential operates in sandbox mode. Changing this forces a new resource.

### Read-Only

- `created_at` (String) RFC3339 creation timestamp.
- `id` (String) SMTP credential UUID.
- `password` (String, Sensitive) One-time SMTP password returned only on create. Preserved in state; omitted from later reads.
- `updated_at` (String) RFC3339 last update timestamp.
- `username` (String) SMTP username.

## Import

Import is supported using the following syntax. For sub-account credentials, import while the resource uses a **child provider alias** (`ImportState` does not store `api_key`); then set resource-level `api_key` with `terraform apply -refresh=false`. See the [sub-account child domain](../guides/sub-account-child-domain) guide.

```shell
# Provider-account credential
terraform import ahasend_smtp_credential.example 00000000-0000-0000-0000-000000000030

# Sub-account credential: ImportState does not store api_key. Import while the
# resource uses a child provider alias so the first Read authenticates as the
# child, then switch to resource-level api_key (see sub-account-child-domain guide).
terraform import ahasend_smtp_credential.example 00000000-0000-0000-0000-0000000000aa/00000000-0000-0000-0000-000000000030
```
